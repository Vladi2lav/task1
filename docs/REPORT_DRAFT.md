## 1. Цель и задачи
Разработать систему из модуля автоматического сбора итогов биржевых торгов с двух площадок (ETS, Каспий) и веб-портала для просмотра, поиска и анализа собранных данных. Пройти полный цикл небольшого data-проекта: анализ источников, проектирование БД, парсинг, серверная часть, интерфейс, развёртывание.

## 2. Анализ источников
- **ETS** (ets.kz): итоги публикуются ежедневными XLSX-файлами в разделах «год → месяц». Официального API нет. Файлы разных периодов отличаются форматом шапки, часть значений хранится формулами `VLOOKUP` на скрытом листе, в файлах 2025 года нет БИН, брокеров и суммы.
- **Каспий** (ccx.kz): страница итогов торгов возвращает «Нет данных» при любых фильтрах. Анализ сетевых запросов показал внутренний JSON-эндпоинт, который отдаёт последние 20 лотов по секции и режиму торгов и только при `max_results=20`.
- Готовых публичных API и парсеров найдено не было.
Подробно: `docs/SOURCES.md`.

## 3. Архитектура и технологии
Python 3.12, Django 5.2, SQLite/PostgreSQL, requests, BeautifulSoup, lxml, openpyxl, APScheduler, Chart.js, pytest, Docker. Схема: парсеры → единый формат записи → БД (с защитой от дублей) → портал (только чтение из БД).
Подробно: `docs/ARCHITECTURE.md`, `docs/DATABASE.md`.

## 4. Что реализовано
- Парсеры ETS и Каспий с приведением к единому формату, защитой от дублей, журналом запусков и обработкой ошибок.
- Ежедневный запуск по расписанию из конфигурационного файла, ручной запуск командой и кнопкой.
- Веб-портал: таблица с пагинацией и сортировкой, 7 комбинируемых фильтров без перезагрузки страницы, страница состояния данных.
- Дополнительно: экспорт в Excel, аналитика с графиками, лента новостей бирж, автотесты, Docker, запуск одним `start.bat`, демо на Vercel, юридические страницы и согласие на cookie.
- Объём данных: [N] записей ETS, [N] записей Каспия, [N] новостей (на дату сдачи — см. `/status/`).

## 6. Проблемы и как решались
- Разный формат XLSX-файлов ETS → поиск колонок по тексту шапки, а не по номерам.
- Формулы вместо значений в ячейках → чтение сохранённых значений и справочника с скрытого листа.
- Неверная дата в заголовке листа → дата берётся из названия файла.
- Пустая страница Каспия → поиск данных через сетевые запросы страницы, обнаружение ограничения `max_results=20`.
- Поиск без учёта регистра по кириллице в SQLite → собственный lookup с Python-функцией.
