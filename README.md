# Итоги торгов бирж ETS и Каспий

Учебный проект (производственная практика, 12 октября — 12 ноября 2026).
Система собирает итоги торгов товарных бирж Казахстана в единую базу данных и показывает их на веб-портале с поиском, фильтрами, сортировкой и экспортом в Excel.

Что такое «итоги торгов»: каждый торговый день биржа публикует, кто у кого что купил (зерно, топливо, уголь, сахар и т.д.), через каких брокеров, по какой цене и на какую сумму.

## Состав

- **Парсеры** (`scrapers/`) — забирают данные с сайтов бирж, приводят к единому формату, сохраняют в БД без дублей.
- **База данных** (`exchanges/`) — справочники (биржи, товары, участники, брокеры), итоги торгов, журнал запусков. Описание: [docs/DATABASE.md](docs/DATABASE.md).
- **Веб-портал** (`portal/`) — таблица торгов, фильтры без перезагрузки страницы, страница состояния данных, аналитика, экспорт в Excel.
- **Планировщик** — ежедневный автоматический сбор и ручной запуск.

Архитектура: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md). Описание источников: [docs/SOURCES.md](docs/SOURCES.md).

## Источники

| Биржа | Адрес | Способ | Статус |
|---|---|---|---|
| ETS | https://ets.kz/documents/trading-results/ | ежедневные XLSX-файлы по страницам «год → месяц» | работает |
| Каспий | https://ccx.kz/trading-and-analytics/trading-results | внутренний JSON сайта (страница итогов пуста) | работает: внутренний JSON сайта, только последние 20 лотов по секции |

## Стек

Python 3.11+, Django 5.2, SQLite (PostgreSQL — по переменным окружения), requests, BeautifulSoup, openpyxl, APScheduler, pytest. Интерфейс — шаблоны Django и JavaScript без фреймворков.

## Установка и запуск

Нужны Python 3.11+ и Git.

```bash
git clone https://github.com/Vladi2lav/task1.git
cd task1
python -m venv .venv
# Windows:   .venv\Scripts\activate
# Linux/Mac: source .venv/bin/activate
pip install -r requirements.txt
python manage.py migrate
```

### Вариант 1. Загрузить готовые данные из дампа

```bash
python manage.py loaddata docs/db/trades_fixture.json
```

Тот же набор данных есть как SQL-скрипт для SQLite: `docs/db/trades_dump.sql` (схема таблиц и данные, без таблиц Django). Загрузка в отдельную пустую базу: `sqlite3 trades.sqlite3 < docs/db/trades_dump.sql`.

### Вариант 2. Собрать данные с сайта биржи

```bash
# первоначальная загрузка истории за 3 месяца (по умолчанию 92 дня)
python manage.py collect_trades --exchange ets

# за произвольный период
python manage.py collect_trades --exchange ets --since 2026-07-14 --until 2026-10-14
```

Повторный запуск безопасен: дубли не создаются.

### Запуск портала

```bash
python manage.py runserver
```

Откройте http://127.0.0.1:8000/ — таблица торгов; `/status/` — состояние данных и ручной запуск сбора; `/analytics/` — графики; `/admin/` — админка (создать пользователя: `python manage.py createsuperuser`).

### Автоматический ежедневный сбор

```bash
python manage.py run_scheduler
```

Расписание и параметры сбора — в [scraper.toml](scraper.toml): время запуска, список бирж, число последних дней для перезагрузки, паузы между запросами. Процесс должен работать постоянно (на сервере — как служба/systemd либо контейнер).

### Docker

```bash
docker compose up --build
```

Портал на http://localhost:8000, планировщик работает отдельным сервисом, база хранится в томе `tradedata`. Первоначальная загрузка:

```bash
docker compose exec web python manage.py collect_trades --exchange ets
```

### Тесты

```bash
python -m pytest
```

Сеть в тестах не используется: страницы и файлы бирж подменяются образцами из `tests/fixtures/`.


## Как работает защита от дублей

Каждая запись получает отпечаток `source_key` (sha1 от биржи, даты, участников, товара, цен и суммы + номер повтора внутри файла) с уникальным индексом в БД. Повторный сбор пропускает уже существующие записи и пишет в журнал число добавленных и пропущенных.

## Ограничения

- **Каспий** отдаёт только последние 20 лотов по секции (сейчас данные есть по углю), без участников и брокеров. История накапливается ежедневными запусками, поэтому планировщик должен работать постоянно. Подробности в [docs/SOURCES.md](docs/SOURCES.md).
- **ETS** не публикует объём, единицу измерения, срок поставки и цену с/без НДС; в файлах 2025 года нет БИН, брокеров и суммы сделки. Эти поля остаются пустыми.
- Если биржа перевыложит исправленный файл, старые строки не удаляются.
