# Итоги торгов бирж ETS и Каспий

Учебный проект (производственная практика, 12 октября — 12 ноября 2026).
Система собирает итоги торгов товарных бирж Казахстана в единую базу данных и показывает их на веб-портале с поиском, фильтрами, сортировкой, графиками, лентой новостей и экспортом в Excel.

Что такое «итоги торгов»: каждый торговый день биржа публикует, кто у кого что купил (зерно, топливо, уголь, сахар и т.д.), через каких брокеров, по какой цене и на какую сумму.

## Состав

- **Парсеры** (`scrapers/`) — забирают итоги торгов и новости с сайтов бирж, приводят к единому формату, сохраняют в БД без дублей.
- **База данных** (`exchanges/`) — справочники (биржи, товары, участники, брокеры), итоги торгов, новости, журнал запусков. Описание: [docs/DATABASE.md](docs/DATABASE.md).
- **Веб-портал** (`portal/`) — таблица торгов, фильтры без перезагрузки страницы, аналитика, новости, состояние данных, экспорт в Excel, юридические страницы.
- **Планировщик** — ежедневный автоматический сбор и ручной запуск.

Документация: [архитектура](docs/ARCHITECTURE.md) · [источники](docs/SOURCES.md) · [развёртывание](docs/DEPLOY.md) · [сверка с ТЗ](docs/TZ_CHECKLIST.md) · [черновик отчёта](docs/REPORT_DRAFT.md).

## Стек

Python 3.11+, Django 5.2, SQLite или PostgreSQL, requests, BeautifulSoup + lxml, openpyxl, APScheduler, WhiteNoise, waitress (Windows) / gunicorn (Linux), pytest. Интерфейс — шаблоны Django и JavaScript без фреймворков, графики — Chart.js.

## Быстрый старт (Windows, без установки)

Python и Git не нужны.

1. Скачайте проект: **Code → Download ZIP** и **распакуйте** архив в любую папку.
2. Дважды щёлкните **`start.bat`**.
3. Через 1–3 минуты (только в первый раз) откроется браузер: http://127.0.0.1:8000/

`start.bat` сам найдёт Python 3.11–3.13, а если его нет — скачает портативный Python в папку проекта (через [uv](https://docs.astral.sh/uv/), в систему ничего не ставится), установит зависимости, создаст файл настроек `.env`, загрузит готовые данные из `docs/db/` и запустит портал и планировщик ежедневного сбора.

| Файл | Что делает |
|---|---|
| `start.bat` | запуск портала (повторный запуск — несколько секунд) |
| `stop.bat` | остановка портала и планировщика |
| `update_data.bat` | собрать свежие итоги торгов и новости (за 7 дней; `update_data.bat --days 92` — за 3 месяца) |
| `run_tests.bat` | автотесты |

Если Windows покажет «Windows защитила ваш компьютер» — «Подробнее» → «Выполнить в любом случае». Подробности и решение проблем — [docs/DEPLOY.md](docs/DEPLOY.md#1-windows-startbat).

## Docker (полное развёртывание)

PostgreSQL 16 + портал (gunicorn) + планировщик, всё перезапускается автоматически.

```bash
cp .env.example .env          # по желанию: пароль БД, адрес сайта и т.д.
docker compose up -d --build  # http://localhost:8000
docker compose logs -f        # логи
docker compose exec web python manage.py collect_trades --days 92   # ручной сбор
docker compose down           # остановка (данные остаются в томе)
```

При первом запуске база заполняется из дампа `docs/db/`. Обновление, резервные копии (`pg_dump`), HTTPS — в [docs/DEPLOY.md](docs/DEPLOY.md#2-docker-полное-развёртывание).

## Vercel (демо)

Публичная демо-версия только для чтения: `api/index.py` + `vercel.json`, база — снимок `deploy/vercel_demo.sqlite3`, сбор данных отключён. Публикация: `npx vercel --prod` или импорт репозитория на https://vercel.com/new. Подробно — [docs/DEPLOY.md](docs/DEPLOY.md#3-vercel-демо-только-для-чтения).

**Персональные данные.** Серверы Vercel находятся за пределами Казахстана, а базы с персональными данными граждан РК должны храниться в РК (Закон РК № 94-V «О персональных данных и их защите», ст. 12 п. 2). Поэтому в демо-снимке индивидуальные предприниматели и крестьянские хозяйства обезличены («ИП (данные скрыты) №N», без ИИН); компании показываются как есть. Полная версия (`start.bat`, Docker) предназначена для размещения на серверах в РК.

## Настройка

Параметры развёртывания — переменные окружения или файл `.env` в корне проекта (образец с пояснениями — [`.env.example`](.env.example); `start.bat` создаёт `.env` сам). Переменные окружения важнее значений из `.env`.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `DJANGO_SECRET_KEY` | — (в режиме отладки — dev-ключ) | секретный ключ; обязателен при `DJANGO_DEBUG=0` (в Docker создаётся сам) |
| `DJANGO_DEBUG` | `1` без `.env`, `0` в `.env.example` | режим отладки |
| `DJANGO_ALLOWED_HOSTS` | `localhost,127.0.0.1,[::1]` (+ `*` при отладке) | адреса сайта через запятую |
| `DJANGO_CSRF_TRUSTED_ORIGINS` | — | полные адреса сайта для форм, например `https://trades.example.kz` |
| `DJANGO_HTTPS` | `0` | `1` — сайт за HTTPS-прокси: защищённые cookie, HSTS, `X-Forwarded-Proto` |
| `DATABASE_URL` | SQLite `db.sqlite3` | `sqlite:///путь` или `postgres://user:pass@host:5432/db` (также поддерживаются старые `SQLITE_PATH`, `POSTGRES_HOST`+`POSTGRES_DB`) |
| `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD` | `trades` | база PostgreSQL в Docker |
| `WEB_PORT`, `WEB_HOST` | `8000`, `127.0.0.1` | порт портала; адрес для `start.bat` (`0.0.0.0` — доступ из локальной сети) |
| `DJANGO_LOG_LEVEL` | `INFO` | уровень логов |
| `DJANGO_LOG_FILE` | `logs/app.log` | файл логов с ротацией (5 × 5 МБ); `off` — только консоль |
| `PORTAL_READ_ONLY` | `0` (на Vercel — всегда `1`) | только чтение: ручной запуск сбора отключён |
| `PORTAL_EXPORT_MAX_ROWS` | `50000` | максимум строк в выгрузке Excel |
| `SITE_OWNER`, `SITE_CONTACT_EMAIL` | `ИМЯ ФАМИЛИЯ`, `ПОЧТА` (заглушки) | владелец сайта и контакт для `/legal/*` |
| `SITE_HOSTING_PROVIDER` | `[хостинг-провайдер]` (на Vercel — `Vercel Inc. (США)`) | хостинг для политики конфиденциальности |
| `LEGAL_EDITION_DATE` | дата из `portal/legal.py` | дата редакции юридических документов |
| `PROJECT_REPO_URL` | `https://github.com/Vladi2lav/task1` | ссылка на репозиторий |
| `DJANGO_SUPERUSER_USERNAME`, `_EMAIL`, `_PASSWORD` | — | администратор, создаётся командой `bootstrap` |
| `BOOTSTRAP_COLLECT` | `0` | `1` — при первом запуске сразу собрать свежие данные с сайтов |

Параметры сбора — в [`scraper.toml`](scraper.toml):

- `[schedule]` — время ежедневного запуска (по умолчанию 18:30 по Алматы), список бирж, сколько последних дней перезагружать;
- `[history]` — глубина первоначальной загрузки истории (92 дня);
- `[news]` — сбор новостей: `enabled` (планировщик собирает новости после итогов торгов), `days`, `max_pages`, `details` (открывать страницу новости ради анонса и картинки);
- `[http]` — паузы между запросами, таймауты, повторы, User-Agent;
- `[sources.*]` — адреса сайтов бирж и лент новостей.

## Команды

Ручная установка (для разработки), нужны Python 3.11+ и Git:

```bash
git clone https://github.com/Vladi2lav/task1.git
cd task1
python -m venv .venv
# Windows:   .venv\Scripts\activate
# Linux/Mac: source .venv/bin/activate
pip install -r requirements-dev.txt
python manage.py bootstrap      # миграции, статика, данные из дампа (если база пуста), администратор
python manage.py runserver      # http://127.0.0.1:8000/
```

| Команда | Что делает |
|---|---|
| `python manage.py bootstrap [--collect] [--no-fixture] [--skip-static]` | подготовка проекта; повторный запуск безопасен |
| `python manage.py collect_trades --exchange ets --days 92` | итоги торгов за последние N дней (`--exchange ets\|caspy\|all`) |
| `python manage.py collect_trades --exchange ets --since 2026-07-14 --until 2026-10-14` | итоги торгов за период |
| `python manage.py collect_news --exchange all --days 92` | новости бирж (`--since ГГГГ-ММ-ДД` вместо `--days`) |
| `python manage.py run_scheduler` | ежедневный сбор по расписанию (процесс работает постоянно) |
| `python manage.py createsuperuser` | администратор для `/admin/` |
| `python scripts/build_vercel_db.py` | собрать снимок демо-базы для Vercel (с обезличиванием ИП) |
| `python scripts/make_dump.py` | выгрузить дампы `docs/db/` (ИП обезличены; `--full` — полный дамп только для локального использования, не коммитить) |

Повторный сбор безопасен: дубли не создаются.

Готовые данные: `docs/db/trades_fixture.json` и `docs/db/news_fixture.json` (`python manage.py loaddata ...` или `bootstrap`), а также SQL-скрипт для SQLite `docs/db/trades_dump.sql` (схема и данные таблиц `exchanges_*`): `sqlite3 trades.sqlite3 < docs/db/trades_dump.sql`.

## Как работает защита от дублей

Каждая запись получает отпечаток `source_key` (sha1 от биржи, даты, участников, товара, цен и суммы + номер повтора внутри файла) с уникальным индексом в БД. Повторный сбор пропускает уже существующие записи и пишет в журнал число добавленных и пропущенных. Новости уникальны по ссылке.

## Ограничения

- **Каспий**: история на сайте — с февраля 2025; объём, единица и место поставки в таблице итогов не публикуются. 14.10.2026 страница итогов временно не работала — на такой случай парсер переключается на внутренний JSON сайта (последние до 100 лотов, без участников) и помечает запуск «С ошибками».
- **ETS** не публикует объём, единицу измерения, срок поставки и цену с/без НДС; в файлах 2025 года нет БИН, брокеров и суммы сделки. Эти поля остаются пустыми.
- Если биржа перевыложит исправленный файл, старые строки не удаляются.
- Демо на Vercel — только чтение, без планировщика, ИП обезличены.
